# DNS and ICMP Traffic Analysis
**Cybersecurity Incident Investigation | Networking | Case Study**

## 1. Project Overview

This project focuses on analyzing DNS and ICMP network traffic to investigate a simulated cybersecurity incident.

In this scenario, customers reported that they were unable to access a company's website. By examining provided tcpdump logs, I analyzed DNS queries, ICMP error responses, and potential causes of the connectivity issue.

The investigation demonstrates how network protocols and packet-level information can help security analysts identify and troubleshoot network-related incidents.

**Project Type:** Simulated Cybersecurity Incident Analysis  
**Tools and Technologies:** tcpdump (provided logs), DNS, UDP, ICMP  
**Focus Areas:** Network Traffic Analysis, Incident Investigation, DNS Troubleshooting

## 2. Learning Objectives

- Interpret network traffic logs generated by tcpdump.
- Identify source and destination IP addresses and port numbers.

- Document findings in a structured cybersecurity incident report.

## 4. Hands-on Practice: Incident Investigation

### 4.1 Incident Scenario

Several customers reported being unable to access the company's website:

`www.yummyrecipesforme.com`

After waiting for the website to load, users received a "Destination Port Unreachable" error.

A cybersecurity analyst examined network traffic logs to determine which protocols were involved and identify possible causes of the failure.

### 4.2 Network Traffic Analysis

The provided tcpdump logs contained outgoing DNS queries and incoming ICMP error messages.

**Network information:**

| Parameter | Value |
|---|---|
| Client IP | 192.51.100.15 |
| DNS Server IP | 203.0.113.2 |
| Requested Domain | yummyrecipesforme.com |
| DNS Query Type | A Record |
| Transport Protocol | UDP |
| Destination Port | 53 |
| Error Response Protocol | ICMP |
| Error Message | UDP Port 53 Unreachable |

**Sample DNS request:**

```text
13:24:32.192571
IP 192.51.100.15.52444 >
203.0.113.2.domain:
35084+ A?
yummyrecipesforme.com. (24)
```

The client attempted to resolve the website's domain name by sending a DNS query to the server using UDP port 53.

**Sample ICMP response:**

```text
13:24:36.098564
IP 203.0.113.2 >
192.51.100.15:
ICMP 203.0.113.2 udp port 53
unreachable length 254
```

The DNS server's IP address returned an ICMP Destination Unreachable message indicating that UDP port 53 was unreachable.

The logs showed three DNS query attempts, each followed by the same type of ICMP error.

### 4.3 Key Findings

1. The client attempted to resolve the company's domain name through DNS.
2. The DNS requests were transmitted using UDP to destination port 53.
3. ICMP Port Unreachable messages were returned for each observed request.
4. Three consecutive DNS queries failed to produce a successful DNS response.
5. The evidence indicates a DNS connectivity or service availability issue.

The available logs establish that DNS queries failed, but they do not conclusively identify the underlying root cause.

### 4.4 Potential Root Causes

Several possible explanations require further investigation:

- A firewall or security rule may be rejecting UDP traffic directed to port 53.
- The DNS service may be unavailable or not listening on the expected port.
- The DNS server may have an incorrect network or service configuration.
- A security incident may have disrupted DNS service availability.

These are hypotheses rather than confirmed findings.

### 4.5 Recommended Investigation Steps

To investigate and resolve the issue, the following actions are recommended:

1. Verify the operational status of the DNS server.
2. Check whether the DNS service is listening on UDP port 53.
3. Review firewall and network security rules.
4. Examine DNS server logs for errors or suspicious activity.
5. Perform controlled DNS queries to verify connectivity.
6. Reexamine network traffic after corrective actions to confirm whether DNS resolution has been restored.

## 5. Challenges and Troubleshooting

**Challenge 1: Understanding different network protocols**

DNS queries were transmitted using UDP, while the error responses were delivered using ICMP.

This demonstrated that different protocols can be involved in the same network troubleshooting process.

**Challenge 2: Interpreting ICMP error messages**

I learned to distinguish an ICMP Port Unreachable error from other ICMP messages, such as Echo Requests and Echo Replies.

**Challenge 3: Identifying the root cause**

Although the traffic logs revealed that UDP port 53 was unreachable, they did not establish why the error occurred.

This highlighted the importance of collecting additional evidence before determining the root cause of a cybersecurity incident.

## 6. Key Takeaways

- DNS commonly uses UDP port 53 for domain name resolution.
- ICMP provides important diagnostic information about network communication failures.
- Repeated error responses can help analysts identify recurring network issues.
- Network traffic analysis can narrow down potential causes of service disruption.
- Effective incident investigation requires separating confirmed observations from assumptions.
